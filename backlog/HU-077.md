## Historia
Como **admin** quiero **poder revisar un pago que otro admin no revisó a tiempo** para **que ningún comprobante quede esperando mientras el asignado no está**.

## Contexto
- **Tipo de usuario:** Admin
- **Corte propuesto:** Corte 1 (MVP)
- **Reglas:** RN-41, RN-42, D-38 (2-oct-2026).
- [HU-020](HU-020.md) deja revisar solo al admin asignado, aunque se le haya pasado la hora; los demás ven el pago sin acciones. D-38 decide que, pasada la hora, cualquier admin activo puede aprobarlo o rechazarlo, y que queda registrado quién lo revisó. El escalamiento automático (que el pago pase solo al siguiente admin) sigue siendo de [HU-034](HU-034.md).

## Criterios de aceptacion
- [x] Dado un pago en revisión cuya hora para el admin asignado ya pasó, cuando otro admin activo lo abre, entonces puede aprobarlo o rechazarlo con las mismas reglas que el asignado.
- [x] Dado un pago en revisión dentro de la hora del asignado, cuando otro admin lo abre, entonces lo ve sin acciones y sabe hasta cuándo es del asignado.
- [x] Dado una revisión, cuando se guarda, entonces queda registrado qué admin la hizo, además del asignado.
- [x] Dado dos admins que revisan el mismo pago a la vez, cuando los dos envían, entonces solo vale la primera revisión y el otro ve que ya se revisó.

## Fuera de alcance
- Reasignar el pago automáticamente al siguiente admin (HU-034).

## Notas tecnicas
Toca `privado.revisar_pago` de HU-020 (Juzou04) con una migración nueva y una columna para quien revisó (por ejemplo `pago.id_admin_revisor`). Coordinar con HU-034 y con HU-074 (pagos de un admin desactivado), que también tocan la asignación.

De la revisión del PR #32 (D-39):
- `acciones.ts` valida el texto de las observaciones antes de comprobar quién revisa. Al cambiar quién puede revisar, comprobarlo primero.
- Cualquier admin ve los pagos y los comprobantes de los demás. Con D-38 eso se necesita, así que se deja.
- [HU-076](HU-076.md) también toca `acciones.ts` (el correo al pagador sale de ahí). El PR que llegue segundo integra al otro.
