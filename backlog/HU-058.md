## Historia
Como **equipo de Calibra** quiero **que la sesión anónima solo se cree para personas y no para bots** para **no llenar Auth de usuarios basura ni agotar el límite de anónimos por IP**.

## Contexto
- **Tipo de usuario:** Tareas técnicas
- **Origen:** HU-004. La documentación de Supabase recomienda con fuerza un CAPTCHA invisible (hCaptcha o Cloudflare Turnstile) cuando se activa el inicio anónimo. La nube limita a 30 anónimos por hora por IP.
- **Pendientes:** elegir el proveedor y quién crea la cuenta (Cloudflare o hCaptcha). Sin eso no pasa a Lista.

## Criterios de aceptacion
- [ ] Dado un visitante, cuando abre una página pública, entonces el CAPTCHA invisible se resuelve sin interacción y la sesión anónima se crea con su token.
- [ ] Dado una petición de inicio anónimo sin token válido, cuando llega a Auth, entonces se rechaza.
- [ ] Dado el entorno local y las pruebas, cuando corren, entonces funcionan con las llaves de prueba del proveedor.
- [ ] Dado el proveedor caído, cuando falla el CAPTCHA, entonces el visitante puede seguir navegando lo público y se le avisa solo al intentar algo que necesite sesión.

## Fuera de alcance
- CAPTCHA en el login de monitores y admins.

## Notas tecnicas
`signInAnonymously({ options: { captchaToken } })` y `[auth.captcha]` en `supabase/config.toml` (provider, secret por `env()`). La llave secreta del proveedor nunca va en el repo. Coordinar con [HU-057](HU-057.md), que configura Auth en el proyecto real.

## Definicion de terminado
- [ ] Criterios de aceptacion cumplidos
- [ ] Pruebas pasan
- [ ] Sin cambios fuera de alcance
