## Historia
Como **equipo de Calibra** quiero **cargar el banco de preguntas en la base del proyecto Supabase nuevo con el mismo comando de siempre** para **que el corte ([HU-057](HU-057.md)) sea solo configurar (D-18) y el diagnóstico arranque con las 10 Evaluaciones activas**.

## Contexto
- **Tipo de usuario:** Tareas técnicas
- **Corte propuesto:** Antes del corte: es dependencia de [HU-057](HU-057.md).
- **Épica:** E1 Diagnóstico y captura de leads
- **Decisiones:** D-18 (el corte es solo configurar), D-62 a (la carga reconoce la materia por su carpeta y respeta lo editado en la app), D-72 a (v10 sale en un proyecto Supabase nuevo; el del prototipo, `uotlhaitdkfroavqkvee`, no se toca nunca).
- **Qué hay hoy:**
  - `npm run contenido:cargar` (`scripts/contenido/convertir.mts`) abre una conexión `pg` con `SUPABASE_DB_URL` y rechaza toda URL que no sea `127.0.0.1` o `localhost` (`convertir.mts:64-70`). Es la barrera que protegía al proyecto del prototipo. `contenido/README.md` dice que la carga solo acepta la base local, y HU-055 dejó la carga en la nube para el corte.
  - La carga corre en una transacción, no borra nada y se puede repetir (`cargar.mts`). Sin `--borradores` solo carga las revisadas.
- **Preguntas abiertas:** ninguna.

## Criterios de aceptacion
- [x] Dada una `SUPABASE_DB_URL` que no es local, cuando se corre `npm run contenido:cargar` sin una bandera nueva y explícita (por ejemplo `--nube`), entonces termina con error sin conectarse, como hoy.
- [x] Dada esa bandera y una URL que contiene el ref del prototipo (`uotlhaitdkfroavqkvee`), cuando se corre, entonces termina con error sin conectarse, diga lo que diga el resto de la URL o de los argumentos.
- [x] Dada la bandera y una URL de otro proyecto, cuando se corre, entonces:
  - se conecta con TLS;
  - imprime el host al que va, sin la contraseña;
  - carga en una transacción como hoy;
  - termina con los mismos conteos y el mismo reporte de Evaluaciones activas que la carga local.
- [x] Dada la bandera con `--borradores`, cuando se corre, entonces termina con error: a la nube solo llegan preguntas revisadas.
- [x] Dada la carga en la nube, cuando termina, entonces `--dry-run` sigue sin conectarse a ninguna base, y la carga local funciona igual que antes (las pruebas de `pruebas/contenido.test.ts` y las de la carga siguen en verde).
- [x] Dados `contenido/README.md` y `docs/pendientes-dvarela.md` §C, cuando se leen, entonces explican cómo cargar el banco en la nube el día del corte: de dónde sale la cadena de conexión del proyecto nuevo y que nunca se usa la del prototipo.

## Fuera de alcance
- Correr la carga contra la nube: se hace en HU-057.
- `scripts/verificar-bd.mjs` (`db:verificar`) sigue solo local; en la nube se usan `supabase db advisors --linked` y las comprobaciones de HU-057.
- `scripts/contenido/migrar-prototipo.mts`: no se vuelve a correr.

## Notas tecnicas
- La barrera nueva es una función pura (bandera, URL) → permitido o el motivo, probada con Vitest: URL local, URL del prototipo con y sin bandera, URL con contraseña (que no se imprime), y `--borradores`.
- Para la prueba de la conexión con TLS basta con revisar las opciones con las que se crea el cliente `pg`. No se necesita una base en la nube en el CI.
- La cadena de conexión del proyecto nuevo está en el panel (Connect, «Session pooler» o conexión directa) y lleva la contraseña de la base. No se escribe en el repo: se pasa como variable de entorno solo para ese comando.
