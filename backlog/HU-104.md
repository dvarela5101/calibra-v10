## Historia
Como **equipo de Calibra** quiero **que las pruebas de integración no fallen cuando la llamada a Cloudflare del CAPTCHA tiene un problema de red** para **no tener que relanzar el CI a mano ni acostumbrarnos a fusionar con un check en rojo**.

## Contexto
- **Tipo de usuario:** Tareas técnicas. La pidió Juzou04 el 19-oct-2026, después de que #86 se fusionara por error con "Base de datos e integracion" en rojo.
- **Corte propuesto:** No frena el corte (HU-057). Solo toca pruebas.
- **Épica:** Transversal (sin épica propia)
- **Qué pasa:** con `[auth.captcha]` activo (HU-058), el Auth local valida cada token de Turnstile llamando a Cloudflare por internet. La llave secreta de prueba acepta cualquier token no vacío, así que, si esa llamada falla, Auth responde `captcha_failed` ("captcha verification process failed") aunque el token sea válido. Cae en pruebas distintas cada vez. Pasó el 19-oct en la corrida 39255372157 (main, un commit que solo tocaba `backlog/`, en `invitaciones-admin.test.ts`) y en la 39318467881 (#86, en `certificados.test.ts` y `correo.test.ts`). El mismo contenido de #86 pasó en verde en main (39319523119).
- **Preguntas abiertas:** ninguna.

## Criterios de aceptacion
- [x] Dado un pedido a Auth con el token de prueba (inicio anónimo, inicio de sesión con contraseña o enlace para restablecer), cuando Auth responde `captcha_failed`, entonces las pruebas de integración lo repiten hasta 3 veces en total, con espera entre intentos, y dejan un aviso en la consola. Cualquier otra respuesta, éxito o error, vuelve sin reintentar.
- [x] Dado `integracion/captcha.test.ts`, cuando se manda el token vacío, entonces la prueba sigue esperando `captcha_failed` sin reintentar: el rechazo sin token se sigue probando igual.
- [x] Dado que la llamada a Cloudflare falle siempre, cuando se agotan los 3 intentos, entonces la prueba falla con el mismo mensaje de hoy: el reintento no esconde un CAPTCHA roto.
- [x] Dado `npm run test:integracion` contra el Supabase local, entonces pasa completo.

## Fuera de alcance
- Las e2e: ahí el token lo manda la app desde sus acciones de servidor, y hasta hoy no han fallado por esto.
- Apagar el CAPTCHA en CI o cambiar la llave de prueba: dejaría de probarse HU-058.
- El código de la app (`src/`).

## Notas tecnicas
- Un ayudante en `integracion/utilidades.ts` que repite el pedido solo si `error.code === "captcha_failed"`. Se usa en `iniciarSesionConClave`, en `Fixtures.crearAnonimo` y en las llamadas directas con `TOKEN_CAPTCHA_DE_PRUEBA` (`auth.test.ts`, `captcha.test.ts`, `cuenta-estudiante.test.ts` e `invitaciones-admin.test.ts`). Nunca en la del token vacío.
- Verificación: `npm run db:reiniciar`, `npm run db:env` y `npm run test:integracion`; `npm run lint` y `npm run typecheck`.
