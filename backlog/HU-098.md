## Historia
Como **equipo de Calibra** quiero **que las pruebas de Vitest que recorren todo el repo terminen holgadas dentro de su tiempo máximo** para **que `npm test` no falle en un equipo cargado cuando el código está bien**.

## Contexto
- **Tipo de usuario:** Tareas técnicas (pruebas).
- **Corte propuesto:** cualquiera; no bloquea a nadie.
- **Origen:** al verificar HU-011 y HU-022 (14-oct-2026), `npm test` falló en el equipo de Juzou04 con «Test timed out in 5000ms» en dos pruebas que pasan solas y en el CI:
  - `pruebas/comision-solo-en-desembolsos.test.ts` (de [HU-050](HU-050.md)): cada una de las reglas A a F llama `hallazgosDe(regla)`, que vuelve a analizar todo `src/` con la API de TypeScript. El mismo trabajo se hace seis veces, cada vez dentro de una prueba con tope de 5 s. Con el equipo libre cada pasada toma unos 0,6 s; con carga, de 5 a 8 s.
  - `pruebas/secretos.test.ts`: lee los 901 archivos versionables (11 MB) y pasa cinco expresiones regulares por cada uno dentro de una sola prueba.
- Con `--testTimeout=60000` las dos pasan (55 de 55): el problema es de tiempo, no de lógica.

## Criterios de aceptacion
- [ ] Dado `pruebas/comision-solo-en-desembolsos.test.ts`, cuando corre, entonces `src/` se analiza una sola vez, fuera del tiempo de cada prueba, y las reglas A a F solo filtran ese resultado. Las pruebas, sus nombres, sus controles positivos y negativos y lo que afirman no cambian.
- [ ] Dado `pruebas/secretos.test.ts`, cuando corre, entonces cada archivo se lee una vez, fuera del tiempo de la prueba, y una sola expresión combinada descarta los que no tienen ningún patrón antes de nombrar cuál encontró. Los patrones y lo que afirma la prueba no cambian.
- [ ] Dadas las dos pruebas sin cambiar el tiempo máximo, cuando corren con el equipo cargado (con otra suite de Vitest a la vez), entonces cada prueba termina muy por debajo de 5 s.
- [ ] Dados los mutantes de siempre (una llave secreta o una cifra de comisión fuera de su lugar, en un archivo nuevo), entonces las dos pruebas siguen poniéndose en rojo.

## Fuera de alcance
- Subir el tiempo máximo de Vitest.
- Cambiar las reglas de D-59 o los patrones de secretos.

## Notas tecnicas
- Verificación: `npx vitest run pruebas/comision-solo-en-desembolsos.test.ts pruebas/secretos.test.ts`, con y sin carga, y `npm test`, `npm run lint` y `npm run typecheck`. No usa la base.

## Definicion de terminado
- [ ] Criterios de aceptacion cumplidos
- [ ] Pruebas pasan
- [ ] Sin cambios fuera de alcance
