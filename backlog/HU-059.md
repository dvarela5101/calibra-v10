## Historia
Como **equipo de Calibra** quiero **comprobar en el servidor el contenido de cada comprobante, limpiar los que nunca llegan a un pago y limitar cuántos sube cada sesión** para **que el bucket privado no se llene de basura ni acepte archivos que no son lo que dicen ser**.

## Contexto
- **Tipo de usuario:** Tareas técnicas
- **Corte propuesto:** Corte 1 (MVP), antes de abrir la app al público
- **Épica:** E6 Pagos y verificación
- **Reglas:** RN-40, RN-41. Sección 14 (comprobantes). Pendiente P-13 (retención de datos).

HU-007 dejó el bucket `comprobantes` funcionando, pero tres cosas quedaron fuera porque exceden su alcance:

- El Storage solo mira el tipo MIME que declara quien sube. La app contrasta los primeros bytes del archivo en el navegador, pero alguien que suba directo a la API puede declarar `image/png` y mandar otro contenido.
- Un archivo subido que nunca llega a un pago (la persona cierra la página, el pago se rechaza al crearse) queda huérfano en el bucket.
- Cualquier sesión anónima puede subir sin tope de cantidad; cada archivo pesa hasta 5 MB.

## Criterios de aceptacion
- [ ] Dado un archivo subido directo a la API con un tipo declarado que no coincide con su contenido, cuando el servidor lo revisa, entonces se descarta y ningún pago puede apuntar a él.
- [ ] Dado un comprobante que lleva más de N horas sin pago (N por definir con P-13), cuando corre la limpieza, entonces se borra con la API de Storage y la llave secreta.
- [ ] Dado una sesión que ya subió N comprobantes en las últimas horas (N por definir), cuando intenta subir otro, entonces se rechaza con un mensaje claro.

## Fuera de alcance
- Lectura automática (OCR) del comprobante.
- Marcar como posible duplicado un `referenciaTransferencia` ya usado (va con [HU-020](HU-020.md)).

## Notas tecnicas
Borrar por SQL está bloqueado por Storage (`storage.protect_delete`): la limpieza usa la API con `service_role`. La revisión del contenido puede vivir en la función que crea el pago ([HU-018](HU-018.md)), que ya tiene que comprobar `rutaEsDelUsuario()`. Definir N y el plazo antes de pasar a Lista.

## Definicion de terminado
- [ ] Criterios de aceptacion cumplidos
- [ ] Pruebas pasan
- [ ] Sin cambios fuera de alcance
